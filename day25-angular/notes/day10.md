# Day 25 — โน้ตวันที่ 10 (e2e, accessibility, ng update, สรุปรอบสอง)

## ทำอะไร
- เพิ่ม e2e ด้วย Playwright (19 ข้อ) รันกับ production build แบบ SSR + mock API และ axe-core สแกน 5 หน้า
- เขียน workflow `day25.yml` (ยังไม่เคยรันบน GitHub) และลอง `ng update` 22.2 → 22.3 ใน scratch

## ที่ได้เรียนรู้
- e2e กับ unit test จับคนละอย่าง: unit test ของ Day 24 ผ่านหมดแต่บั๊ก select ที่ server เขียนค่าผิดต้องเห็นจากภาพ ตอนนี้เทสต์ e2e ตรวจ HTML ดิบ (`request.get`) และ DOM หลัง hydrate ทั้งสองแบบ
- เขียน e2e ครั้งแรกล้ม 2 จาก 18 ด้วยเหตุที่เป็นของเทสต์เอง ไม่ใช่ของแอป: (1) คาดว่า guard ส่งกลับ `/claims` แต่จริงมี `?login=required` (2) กรอง PENDING แล้วรีบอ่านสถานะ ได้ 0 ใบ เพราะระหว่างโหลดรายการหาย (ข้อจำกัดที่จดไว้ใน Day 23) แก้โดยรอด้วย `expect.poll` ไม่ใช่ `waitForTimeout`
- เทสต์ "สร้างเคลมแล้วอยู่ใบแรก" เปิดโปงบั๊กใน mock (ต่อท้ายลิสต์) ไม่ใช่ในแอป ตัว mock ไม่มีเทสต์ของตัวเอง e2e เลยเป็นตัวตรวจ mock ไปด้วย
- mock มี state เดียว จึงต้องรัน worker เดียวและ reset ก่อนทุกเทสต์ (`POST /__reset`) ถ้าจะรันขนานต้องแยกข้อมูลต่อเทสต์
- `getByRole` / `getByLabel` ใช้เป็นตัวตรวจ a11y ไปในตัว: ถ้าปุ่มหรือช่องไม่มีชื่อที่อ่านออกเสียง locator หาไม่เจอ เทสต์ก็ล้ม ทำให้พังแล้ว 2 แบบ (ลบ label) ถูกจับโดยเทสต์ปกติ ไม่ใช่โดย axe
- axe ผ่านทุกหน้าตั้งแต่รอบแรก ตอนแรกสงสัยว่าตรวจไม่จริง จึงทำให้สีของ badge จางลงดู ได้ `color-contrast (serious)` ทันที (ดูภาพที่ 4)
- `ng update`: ชุด `@angular/*` ขยับพร้อมกันหมดรวม ssr/platform-server/build ไม่ต้องสั่งแยก ในครั้งนี้ไม่มี migration อัตโนมัติ lock เปลี่ยนเยอะ (~1,900 บรรทัด) ควรเป็น commit แยก
- Day 24 เคยติดเรื่อง `ng add @angular/ssr` จะลง 22.3 ชนกับ core 22.2.6 ตอนนี้ลองอัปทั้งชุดเป็น 22.3.0 ผ่านหมด (unit/build/e2e) จึงน่าจะเป็นทางที่ง่ายกว่าตรึง ssr ไว้ที่ 22.2.8 แต่ยังไม่ได้ทำจริงกับ day25-angular
