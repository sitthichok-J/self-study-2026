# Day 13 — บันทึกการทดลอง (จากผลรันจริงเท่านั้น)

ข้อมูลทั้งหมดเป็นข้อมูลสมมติ ตัวเลขยกมาจาก `run-results.md` (run-all ผ่าน 126/126 ทั้งรอบแรกและรอบสุดท้ายหลังเพิ่มเทสต์), `security-scan.md` และภาพใน `notes/screens/`

## 1. เพิกถอน access token
- login ได้ token แล้วเรียก API ผ่าน Kong ได้ 200, logout โดยส่ง Bearer ไปด้วยได้ 204, ใช้ token เดิมต่อได้ 401 ทันทีทั้งที่ Kong และ API (exp ยังไม่หมด)
- ใน valkey มี `rev:jti:<jti>` ค่าเป็น `1` มี TTL ไม่มี token เก็บอยู่ ภาพ `redis-insight-valkey.png` (key ที่เกิดจากการกด logout เองบนหน้า UI, TTL 180 วินาที)
- refresh token ถูกใช้ซ้ำ: access token ของ bob ที่ออกก่อนหน้าตายหมด (`rev:user:bob`) และ login ใหม่ได้หลังข้ามวินาที
- valkey หยุด: API ตอบ 503 + `Retry-After: 5` (healthz 200, token มั่ว 401) restart แล้ว token ที่ logout ไว้ยัง 401 (AOF ทำงาน)

## 2. rate limit ต่อ user (ตั้ง 40/นาทีสำหรับทดสอบ)
- 40 ครั้งแรก 200, อีก 5 ครั้ง 429 + `Retry-After` 60 ผู้ใช้อื่นและ /healthz ไม่โดน

## 3. ตรวจเคลมโดยเจ้าหน้าที่
- เคลม 30,000 บาท: PENDING เหตุผล `needs_review`, เจ้าของกดอนุมัติได้ 403, staff อนุมัติได้ 200 (`manual_approved`), ตัดสินซ้ำได้ 409, ยอด 20,000 อนุมัติอัตโนมัติ
- ลองด้วยมือบนหน้า UI: ops ส่ง 35,000 บาท -> รอเจ้าหน้าที่ตรวจ -> กดอนุมัติ (ปุ่มเปลี่ยนเป็น "ยืนยันอนุมัติ") -> "เจ้าหน้าที่อนุมัติ" alice ส่ง 30,000 บาท เห็นสถานะรอตรวจและไม่มีปุ่มตัดสิน (ภาพ `ui-*.png`)

## 4. Mutation test (แก้โค้ดให้ผิดแล้วดูว่าเทสต์จับได้ไหม)
- Go 38 จุด: รอบแรกจับได้ 35, ไม่จับ 3 (1 จุดเทียบเท่า พฤติกรรมไม่เปลี่ยน, 2 จุดเป็นช่องว่างจริง: ตอน limiter ล่มไม่ได้เช็กว่า body ไม่ว่าง และ `Retry-After` ขั้นต่ำ 1 ไม่มีเทสต์) เพิ่มเทสต์แล้วรันซ้ำจับได้ 37 จาก 38 เหลือจุดเทียบเท่าจุดเดียว
- Vue 20 จุด: จับได้ 19 เหลือ 1 ("ยิงซ้ำตอนกำลังตัดสิน") ซึ่งเป็นการป้องกันซ้ำซ้อน เพราะปุ่มถูก disable อยู่แล้ว เพิ่มเทสต์ว่าปุ่ม disable และ API ถูกเรียกครั้งเดียว Vue ตอนนี้ 214 ข้อ
