# ข้อผิดพลาด Go ที่เคยเจอ / เกือบเจอ

โค้ดพิสูจน์ของแต่ละข้ออยู่ใน `internal/demo` พร้อมเทสต์

## 1. append แล้ว slice สองตัวทับกัน
`a := make([]int, 3, 10)` แล้ว `b := append(a, 100)`, `c := append(a, 200)` ทั้งคู่ใช้ array เดียวกัน ค่า `b[3]` เลยกลายเป็น 200
ถ้า cap เต็มจะ reallocate แล้วแยกกัน พฤติกรรมเลยเปลี่ยนตามขนาดข้อมูล ดูได้จาก `AppendSharing` / `AppendRealloc`
หลีกเลี่ยง: ถ้าจะแตกกิ่งจาก slice เดียวให้ `slices.Clone` ก่อน หรือใช้ full slice expression `a[:3:3]`

## 2. เขียนลง nil map
`var m map[string]int; m["a"] = 1` panic แต่อ่านได้ปกติ (ได้ zero value)
หลีกเลี่ยง: `make` ก่อนเขียน หรือสร้างตอนใช้ครั้งแรกแบบ `Counter.Inc` ให้ zero value ใช้ได้เลย

## 3. error ที่เป็น nil pointer ห่อใน interface
ฟังก์ชันที่ return `*MyErr` ที่เป็น nil ผ่าน type `error` จะได้ interface ที่ `!= nil` (มี type แต่ value เป็น nil) แล้ว `if err != nil` เข้าเงื่อนไขทั้งที่ไม่มี error
หลีกเลี่ยง: อย่าประกาศตัวแปรชนิด pointer ของ error แล้ว return ตรงๆ ให้ `return nil` ชัดๆ ตอนไม่มี error ดู `BuggyFail` / `FixedFail`

## 4. defer ในลูป
defer ทำงานตอนจบฟังก์ชัน ไม่ใช่จบรอบ ถ้าวนเปิดไฟล์ 10,000 ไฟล์แล้ว defer Close จะค้างทั้งหมดจนจบฟังก์ชัน
หลีกเลี่ยง: แยกตัวลูปหนึ่งรอบเป็นฟังก์ชันย่อย (`DeferPerIteration`) หรือ Close เองตอนจบรอบ
อีกเรื่องที่เกี่ยวกัน: อาร์กิวเมนต์ของ defer ถูกประเมินตอนประกาศ ส่วน closure อ่านค่าตอนทำงานจริง

## 5. log แล้ว return error ซ้ำหลายชั้น
ถ้าทุกชั้น log แล้ว return ต่อ จะได้ log เรื่องเดียวกันซ้ำหลายบรรทัด และไม่รู้ว่าอันไหนต้นเหตุ
หลีกเลี่ยง: ชั้นล่างห่อด้วย `fmt.Errorf("add: %w", err)` แล้ว return อย่างเดียว ไปแสดง/log ที่ชั้นบนสุดครั้งเดียว (ใน `cmd/tasks/main.go`) และใช้ `errors.Is/As` ตรวจชนิด ไม่ใช้เทียบข้อความ

## แถม: loop variable
