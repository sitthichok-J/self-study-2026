# กฎของฉันสำหรับ concurrency ใน Go

1. **ผู้ส่งเป็นคนปิด channel** ผู้รับไม่ปิด ถ้ามีผู้ส่งหลายคน ให้มี goroutine กลางรอ `wg.Wait()` แล้วปิดครั้งเดียว (ดู `pipeline.Merge`) ปิดซ้ำหรือส่งใส่ช่องที่ปิดแล้วคือ panic
2. **ทุก goroutine ต้องมีทางจบที่มองเห็นได้ตั้งแต่ตอนเขียน** ก่อนพิมพ์ `go` ให้ตอบให้ได้ว่า "อะไรทำให้มันจบ" (channel ปิด หรือ ctx cancel) และทุกการส่ง/รับที่อาจ block ให้ `select` กับ `ctx.Done()` (ดู `leak.Fixed`)
3. **context เป็นพารามิเตอร์แรกเสมอ ไม่เก็บใน struct** และเรียก `cancel()` ด้วย `defer` ทุกครั้งที่สร้างด้วย `WithCancel/WithTimeout` งาน I/O ทุกชนิดต้องรับ ctx
4. **ปกป้อง state ด้วย mutex/atomic ส่งต่อ ownership ของงานด้วย channel** ถ้าไม่แน่ใจว่าเลือกอันไหน ถามว่า "ข้อมูลนี้มีใครเป็นเจ้าของคนเดียวตอนไหน" ถ้าเจ้าของเปลี่ยนมือ ใช้ channel ถ้าหลายคนอ่านเขียนพร้อมกัน ใช้ lock
5. **จำกัด concurrency เสมอ และรันเทสต์ด้วย `-race` ทุกครั้ง** อย่าสร้าง goroutine ไม่จำกัดจากข้อมูลขาเข้า (ใช้ worker pool หรือ `SetLimit`) และอย่าถือว่าเทสต์ผ่านโดยไม่มี `-race` แปลว่าไม่มี race
