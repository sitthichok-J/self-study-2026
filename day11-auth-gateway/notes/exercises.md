# แบบฝึกหัด Day 11

จดผลจริงใต้แต่ละข้อ (รันบนเครื่องตัวเองวันที่ 05/11/2026 ตัวเลขทั้งหมดมาจาก `run-results.md`, `security-scan.md` และเทสต์ที่รันจริง)

## 1. โจมตีตัวเอง: login และ refresh

ลองให้ครบแล้วดูว่าระบบตอบอะไร:

- ใช้ refresh token ซ้ำครั้งที่สอง (ต้องถูกปฏิเสธ และสายนั้นต้องถูกเพิกถอนทั้งหมด)
- ใช้ refresh token ของ user A ไปขอ access token ในนาม user B
- แก้ payload ของ access token แล้วส่งเข้า Kong และเข้า API ตรงๆ
- ใช้ token หมดอายุ, token ที่ alg เป็น none, token ที่ iss/aud ผิด
- login ผิดหลายครั้งติดกัน ดูว่า rate limit ทำงานที่ endpoint login ด้วยไหม
- ดูว่าข้อความ error ของรหัสผ่านผิดกับ user ไม่มีอยู่เหมือนกันทุกบิตหรือไม่ รวมเวลาที่ใช้ตอบ

ผล: ทำเป็นขั้นใน `scripts/run-all.ps1` ยิงผ่าน Kong จริง (ผ่านทั้งหมด)

- ใช้ refresh token ซ้ำครั้งที่สอง: ได้ 401 และ token ใหม่ของสายเดียวกันถูกเพิกถอนด้วย (DB: แถวของ alice ถูกเพิกถอน 2 จาก 4 แถว ใช้แล้ว 2) log มี `refresh_reuse` 1 ครั้ง
- refresh token ของ bob ได้ access token ในนาม bob เท่านั้น (sub มาจากแถวใน DB ไม่ใช่จาก client) ขอในนาม user อื่นไม่ได้เพราะไม่มีช่องให้ระบุ
- แก้ payload แล้วส่งเข้า Kong: 401 ตอบโดย Kong (`{"message":"Unauthorized"}`) ส่วน alg=none ก็ 401 ที่ Kong ยิงตรงเข้า API ตรวจซ้ำอีกชั้น (เทสต์ใน Go)
- token หมดอายุและ iss/aud ผิด: ครอบคลุมด้วยเทสต์ Go (ตัวออก token ตั้งเวลาได้) ไม่ได้ยิงผ่าน Kong ใน run-all เพราะเครื่องมือ mint ไม่ออก token หมดอายุให้
- token ใน query string: Kong ตอบ 401 แต่รอบแรก log ของ Kong มี token ติดอยู่ เพราะ access log บันทึก URL เต็ม (ดูข้อ 4) รอบสุดท้ายใช้ token ใหม่ที่ไม่ใช่ของ session ในการทดสอบ log จึงสะอาด
- login ผิดต่อเนื่อง 30 ครั้ง: 401 อยู่ 8 ครั้ง แล้ว 429 อีก 22 ครั้ง (limit 20 ครั้ง/นาที/IP รวมที่ยิงก่อนหน้า) header `X-RateLimit-Remaining-Minute` = 0, `Retry-After` = 47
- user ไม่มี กับ user มีแต่รหัสผิด: body เหมือนกันทุกตัวอักษร (`{"error":"invalid username or password"}`) ส่วนเวลาวัดได้ 4102ms กับ 121ms แต่เป็นตัวอย่างเดียวและครั้งแรกของ connection (ยังไม่ได้วัดจริงจัง จึงยังบอกไม่ได้ว่าเวลาตอบเท่ากัน)


## 2. Rate limit

- ตั้งเพดานให้เหมาะกับการใช้ปกติของ UI แล้วยิงเกินเพื่อให้ได้ 429
- เช็กว่า header บอกโควต้าที่เหลือ และ UI แสดงข้อความที่อ่านรู้เรื่องเมื่อโดน 429
- คิดว่าจะแยกเพดานต่อ IP กับต่อ user ต่างกันอย่างไร

ผล: ตั้งเพดาน 20 ครั้ง/นาที/IP ที่ `/api/auth` และ 120 ครั้ง/นาที/IP ที่ `/api` ยิงเกินแล้วได้ 429 พร้อม header โควต้าตามข้อ 1 ส่วนข้อความที่อ่านรู้เรื่องใน UI เมื่อโดน 429 และการแยกเพดานต่อ IP กับต่อ user ยังไม่ได้ทำ/ไม่ได้ลอง ตอนนี้จำกัดต่อ IP อย่างเดียว (บันทึกใน SECURITY.md)


## 3. ทำให้เทสต์พิสูจน์ตัวเอง (mutation)

แก้โค้ดจงใจในส่วน auth ทีละจุดแล้วดูว่าเทสต์ล้มจริง จดจำนวนที่แก้และจำนวนที่เทสต์จับได้ เช่น

- ตัดการตรวจ exp
- ไม่หมุน refresh token หลังใช้
- ไม่เพิกถอนสายเมื่อใช้ซ้ำ
- เก็บ refresh token ดิบแทน hash
- ถอด flag HttpOnly/SameSite ออกจาก cookie
- ให้ Kong ข้ามการตรวจ JWT บาง route

ผล: ฝั่ง Go แก้โค้ดจงใจ 30 จุดในส่วน auth (ตัดตรวจ exp, ไม่หมุน refresh, ไม่เพิกถอนสายเมื่อใช้ซ้ำ, เก็บ token ดิบ, ถอด flag cookie ฯลฯ) เทสต์จับได้ 30/30 รอบแรกรอดมา 2 จุด (ค่า iteration ขั้นต่ำของ PBKDF2 กับข้อความตอน login ผิด) จึงเพิ่มเทสต์แล้วรันใหม่ได้ 30/30 ฝั่ง Vue ยังไม่ได้ทำ mutation (ไม่มีตัวเลข) เทสต์ Vue รันได้ 164 ข้อผ่าน ส่วนข้อ "ให้ Kong ข้ามการตรวจ JWT บาง route" ไม่ได้ทดลอง มีแค่เทสต์ static ที่เช็ก config (jwt plugin อยู่ที่ service claims-api และไม่อยู่ที่ auth-api)

## 4. ทบทวนสิ้นวัน

- อะไรที่เทสต์ผ่านแต่ใช้งานจริงพัง
- ข้อจำกัดที่ปิดแล้ว กับที่ยังเหลือ (secret ร่วม, ไม่มี key rotation, ฯลฯ)
- เวลาที่ใช้จริงเทียบกับที่ประเมินไว้

ผล:

- เทสต์ผ่านแต่ใช้งานจริงพัง: (1) สคริปต์ตรวจของผมเองส่ง header Cookie ผ่าน PowerShell แล้วไม่ถึง API ทำให้ refresh ได้ 401 ทั้งที่ API ถูก ต้องเปลี่ยนไปส่งผ่าน session ของ PowerShell จึงผ่าน (เทียบโดยยิงตรงเข้า API ก็ 401 เหมือนกัน เลยรู้ว่าไม่ใช่ Kong) (2) รอบแรก stack ของ Day 10 ยังจองพอร์ต 8080 อยู่ run-all จึงตรวจกับ API ตัวเก่า ได้ผ่านปลอมหลายข้อ มาเห็นว่าผิดตรง migration 000003 ไม่มี ตอนนี้ run-all ปิด stack ของ Day 8–10 ก่อนยกเอง (3) การทดสอบ token ใน query string ทำให้ token จริงไปอยู่ใน access log ของ Kong (4) static test สแกนเจอ key ใน `certs/` กับ token ในไฟล์ผล แก้ให้ข้ามโฟลเดอร์ที่สร้างตอนรันและกรอง JWT ก่อนเขียนไฟล์ผล
- ผลรันสุดท้าย: run-all ผ่าน 86/86 ขั้น, Go test + go vet ผ่าน, static test 44 ข้อ, Vue 164 ข้อ
- สแกน: govulncheck ไม่พบ, Trivy image และ go.mod และ npm 0 รายการ พบ 1 รายการที่ `web/Dockerfile` (ไม่มี USER) แก้เป็น `USER 101` แล้วสแกนซ้ำเหลือ 0 gitleaks เหลือ 4 รายการ ทั้งหมดเป็นไฟล์ที่ run-all สร้างและ git-ignore (`.env` 2 จุด, `certs/server.key`, `gateway/.rendered/kong.yml`) ส่วนค่าปลอมในเทสต์ 2 จุดใส่ใน `.gitleaksignore`
- ข้อจำกัดที่ปิดแล้ว: ไม่มี token ที่ทางเข้า, ไม่มี refresh/revocation, ไม่มี TLS ที่ gateway, ไม่มี rate limit ที่ทางเข้า ที่ยังเหลือ: secret ร่วม HS256 ไม่มี key rotation, UI ยังเสิร์ฟผ่าน http, cert self-signed, rate limit นับในหน่วยความจำและจำกัดต่อ IP อย่างเดียว, access token เพิกถอนไม่ได้ก่อนหมดอายุ, ยังไม่ได้ลอง UI ด้วยมือบนเบราว์เซอร์ในรอบนี้ (ผ่านเทสต์ component และ API เท่านั้น)
- เวลาที่ใช้จริง: ประมาณ 1 วันตามที่ประเมิน แต่ส่วนรันและแก้ตอนทดสอบจริงบนเครื่องใช้เวลานานกว่าที่คาด (รันซ้ำ 6 รอบ) ตัวเลขนาทีจริงไม่ได้จับเวลาไว้
